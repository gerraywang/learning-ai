## 概要
1 画面だけの静的な Web アプリ。サーバーは持たない。ロジック・保存・画面の 3 つに分け、
ロジックと保存は DOM に触れない関数にして単体テストし、画面は requirements.md の受け入れ条件を
そのまま画面テストにする。

## 技術の選択と理由
| もの | 選択 | 理由 |
|---|---|---|
| 言語 | JavaScript（ES Modules）。TypeScript は使わない | 画面 1 つで小さい。生成されたコードを全部読める大きさに保つ |
| UI | フレームワークなし（DOM API）。状態が変わるたびに一覧を丸ごと描き直す | 部品が少なく、依存を増やす理由がない。数百件なら描き直しで十分速い |
| 保存 | localStorage | 利用者の指定（ブラウザを閉じても残す【要件 6.3】）。sessionStorage はタブを閉じると消えるので使わない |
| 開発サーバー・ビルド | Vite 8.3.x | 素の JS のままで開発サーバーとビルドが使える |
| テスト | Vitest 5.1.x ＋ jsdom 31.0.x | Vite と設定を共有できる。jsdom で画面の操作を再現できる |
| 実行環境 | Node.js 24.15 以上 | jsdom 31 の条件。この端末には 24.22.3 が入っている（2026-11-22 確認） |

- ランタイム依存（ブラウザで読み込むライブラリ）は 0。開発時依存は上の 3 つだけ
- バージョンは npm registry で 2026-11-22 に確認。実装時に要確認

## アーキテクチャと部品

```text
index.html          画面の骨組み（下の「画面の要素」）
src/main.js         入口。localStorage と「今日」を用意して app を起動する
src/todo.js         ロジック（純粋関数）: 入力の検証・追加・内容の編集・完了の切り替え・削除・期限切れの判定・絞り込み
src/storage.js      保存と読み込み。Storage を引数で受け取り、失敗は戻り値で返す
src/app.js          画面の描画と操作。todo.js と storage.js をつなぐ
src/style.css       見た目
tests/unit/         todo.js・storage.js の単体テスト（Node 環境）
tests/ui/           requirements.md の受け入れ条件の画面テスト（jsdom 環境）
tests/helpers/      偽の Storage、画面を起動するヘルパー
```

### 操作の流れ（追加の例）

```text
利用者 ─ 追加 ─▶ app.js ─ validate(入力, 今日) ─▶ todo.js
                   │◀──── 誤りの一覧 or 正しい値 ───┘
                   ├─ 誤りあり: 誤りをすべて表示、入力は残す【1.7, 1.8】
                   └─ 誤りなし: addTodo ─▶ save(storage) ─▶ 描き直し、入力欄を空に、誤りの表示を消す【1.6, 1.9, 6.1】
```

完了・未完了の切り替えと削除も同じで、「状態を変える → すぐ保存 → 描き直す」【6.1】。
絞り込みは状態（選んでいる表示）だけを変えて描き直し、保存しない【5.5】。

### 操作の流れ（内容の編集）【要件 8】

```text
利用者 ─ 「編集」 ─▶ app.js: 編集中の行を覚えて描き直す（保存しない）。その行は入力欄に変わる【8.1】
利用者 ─ 確定 ───▶ app.js ─ validateTitle(入力) ─▶ todo.js
                   │◀──── 誤りの一覧 or 正しい値 ───┘
                   ├─ 誤りあり: 内容は変えない。行の中に誤りを表示、入力は残して編集を続ける【8.4〜8.6】
                   └─ 誤りなし: editTodo ─▶ save(storage) ─▶ 編集を終えて描き直す【8.2, 8.7, 6.1】
利用者 ─ 取り消し ─▶ app.js: 編集を終えて描き直す。保存しない【8.3, 8.7】
```

- 編集中の行は画面の状態 `editing` に 1 つだけ持つ【8.9】。保存しないので、再読み込みすると編集していない状態で開く【8.11】
- 編集中にほかの操作（別の行の「編集」・追加・完了の切り替え・削除・表示の切り替え）をしたら、
  まず `editing` を空にしてから、その操作をいつもどおり行う【8.10】。追加で誤りが出ても、編集は取り消したまま
- フォーカス【7.2】: 編集を始めたら入力欄へ。確定できなかったら入力欄に残す。確定・取り消しのあとは、その行の「編集」ボタンへ戻す

## データモデル

### Todo
| 項目 | 型 | 説明 | 要件 |
|---|---|---|---|
| `id` | string | `crypto.randomUUID()`。内容と期限が同じ TODO を見分けるため | 1.10, 4.1 |
| `title` | string | 前後の空白を除いた内容。1〜200 文字 | 1.2, 1.4, 1.5 |
| `done` | boolean | 完了なら `true`。追加時は `false` | 1.1, 3.1, 3.2 |
| `due` | string | 期限。`YYYY-MM-DD`。**必須**（lab1 と違い `null` はない） | 1.3, 2.2 |

- 並び順は配列の順（追加した順）。順番のための項目は持たない【1.11】
- 文字数は JavaScript の文字列の長さで数える（絵文字などで見た目の文字数とずれることは許容）

### 画面の状態（app.js が持つ。保存しない）
| 項目 | 説明 |
|---|---|
| `todos` | Todo の配列 |
| `filter` | `all` / `active` / `completed`。開いたときは `all`【5.5】 |
| `today` | 開いたときの端末の日付 `YYYY-MM-DD`。開いている間は変えない【2.5】 |
| `inputErrors` | 入力の誤りの一覧（下の「入力の誤り」） |
| `notice` | 保存・読み込みについてのお知らせ（1 つ） |
| `editing` | 編集中の行。`null` か `{ id, draft, errors }`（`draft` は入力中の文字、`errors` は編集の誤り）。開いたときは `null`【8.9, 8.11】 |

### 保存形式（localStorage）
- キー: `sdd-kiro-todo`（lab1 と別のキー）
- 値: `{"version":1,"todos":[{"id":"…","title":"…","done":false,"due":"2026-11-30"}, …]}`
- 操作のたびに全体を書き直す【6.1】

## インターフェース

### todo.js（純粋関数）
| 関数 | 振る舞い | 要件 |
|---|---|---|
| `validateTitle(title)` | 内容だけを検証する。0 件なら `{ ok: true, title }`（前後の空白を除いたもの）、あれば `{ ok: false, errors }`。追加と編集で同じ決まりを使うため | 1.2, 1.4, 1.5, 8.2, 8.4, 8.5 |
| `validateInput({ title, due }, today)` | 誤りの一覧を返す。0 件なら `{ ok: true, title, due }`（title は前後の空白を除いたもの）。内容の検証は `validateTitle` を使う | 1.2〜1.5, 1.8, 2.1 |
| `addTodo(todos, { title, due })` | 末尾に未完了で追加した新しい配列 | 1.1, 1.10, 1.11 |
| `editTodo(todos, id, title)` | 指定した 1 件の `title` だけを変えた新しい配列（`id`・`due`・`done`・順番は変えない）。検証は呼ぶ側で済ませる | 8.2, 8.8 |
| `toggleTodo(todos, id)` | 指定した 1 件の `done` を反転 | 3.1, 3.2 |
| `removeTodo(todos, id)` | 指定した 1 件を除く | 4.1 |
| `isOverdue(todo, today)` | `!done && due < today`（`YYYY-MM-DD` は文字列の大小が日付の前後と一致する） | 2.3, 2.4 |
| `filterTodos(todos, filter)` | 選んだ表示に合うものを順番どおりに返す | 5.1〜5.3 |
| `toDateString(date)` | 端末のローカル日付を `YYYY-MM-DD` で返す | 2.2 |

### storage.js
| 関数 | 振る舞い | 要件 |
|---|---|---|
| `load(storage)` | `{ todos, status }`。status は `ok` / `corrupt`（壊れている）/ `unavailable`（読めない）。壊れた値は消さない | 6.2, 6.5 |
| `save(storage, todos)` | `{ ok: boolean }`。例外を外に出さない | 6.1, 6.4 |

### 画面の要素（テストはこのラベル・文言で要素を探す）
| 要素 | 作り | ラベル・文言 | 要件 |
|---|---|---|---|
| 内容の入力欄 | `<input type="text">` | ラベル「内容」 | 1.1 |
| 期限の入力欄 | `<input type="date" required min="今日">` | ラベル「期限」 | 1.3, 2.1 |
| 追加ボタン | `<button type="submit">`（Enter でも追加） | 「追加」 | 1.1, 7.2 |
| 入力の誤り | フォームの下の `<ul role="alert">`。誤り 1 つにつき `<li>` 1 つ | 下の「入力の誤り」 | 1.8, 1.9 |
| お知らせ | `<p role="status">` | 下の「お知らせ」 | 6.4, 6.5 |
| 表示の切り替え | ボタン 3 つ。選んでいるものは `aria-pressed="true"` | 「すべて」「未完了」「完了」 | 5.1〜5.3 |
| 一覧 | `<ul>` | ラベル「TODO の一覧」 | 1.11 |
| 一覧の 1 行 | `<li data-id="…">`。完了なら `done` クラス、期限切れなら `overdue` クラス | — | 3.1, 2.3 |
| 完了チェック | 行の中の `<input type="checkbox">`。ラベルは内容 | — | 3.1, 3.2 |
| 内容 | テキストとして表示（`textContent`。HTML として解釈しない） | — | 1.12 |
| 期限 | 「期限: YYYY-MM-DD」 | — | — |
| 期限切れの印 | 「期限切れ」の文字（色だけに頼らない） | 「期限切れ」 | 2.3 |
| 削除ボタン | 行の中の `<button>`。読み上げ名は「<内容> を削除」 | 「削除」 | 4.1 |
| 編集ボタン | 行の中の `<button>`。読み上げ名は「<内容> を編集」。編集中の行には出さない | 「編集」 | 8.1 |
| 編集の入力欄 | 編集中の行だけ、内容の代わりに `<form class="edit-form">` の中の `<input type="text">`。読み上げ名は「内容を編集」。値は今の内容から始める | — | 8.1 |
| 編集の確定 | 編集フォームの `<button type="submit">`（入力欄で Enter でも確定） | 「保存」 | 8.2, 7.2 |
| 編集の取り消し | 編集フォームの `<button type="button">`（入力欄で Esc でも取り消し） | 「取り消し」 | 8.3, 7.2 |
| 編集の誤り | 編集フォームの中の `<ul role="alert" class="edit-errors">`。誤り 1 つにつき `<li>` 1 つ | 下の「入力の誤り」の内容の 2 つ | 8.4, 8.5, 8.7 |
| 空の表示 | 一覧の代わりに出す文 | 0 件:「TODO はありません」／絞り込みで 0 件:「該当する TODO はありません」 | 5.6, 5.7 |

- 期限の入力欄の `min` は過去を選びにくくするための補助。手で入力された過去の日付は `validateInput` で必ず弾く【2.1】
- 見分ける印（`done`・`overdue` クラス、「期限切れ」の文字）があれば、【3.1】【2.3】を満たしたとする（指摘 T2）
- 編集中の行も、完了チェック（読み上げ名は今の内容）・期限・期限切れの印・削除ボタンはそのまま出す。押したら 8.10 のとおり編集を取り消してから操作する

### 入力の誤り（当てはまるものをすべて、この順に出す）【1.8】
| 条件 | 文言 | 要件 |
|---|---|---|
| 内容が空・空白だけ | 内容を入力してください | 1.2 |
| 内容が 200 文字を超える | 内容は 200 文字以内で入力してください | 1.4 |
| 期限が空 | 期限を入力してください | 1.3 |
| 期限が今日より前 | 期限は今日以降の日付を入力してください | 2.1 |

- 内容の編集【8.4, 8.5】では、上の 2 つ（内容の誤り）だけを、同じ文言で編集フォームの中に出す。追加の誤り（フォームの下）とは別の場所

### お知らせ【6.4, 6.5】
| 場面 | 文言 |
|---|---|
| 起動時に保存先が使えない | この端末に保存できません。閉じると内容は消えます |
| 保存に失敗した（容量不足など） | 保存できませんでした。閉じると内容は消えます |
| 保存されたデータが壊れていた | 保存されたデータを読み込めませんでした |

- お知らせは 1 つだけ出す。同じ文言をくり返し出さない（同じ原因につき 1 回）
- 保存の失敗のお知らせは、次に保存できるまで残す。読み込み失敗のお知らせは、次に保存できたら消す

## エラー処理
| 起きること | 扱い | 要件 |
|---|---|---|
| 入力の誤り | 追加しない。誤りをすべて表示、入力は残す。次に追加できたら誤りを消す | 1.7〜1.9 |
| 編集の誤り | 内容を変えない。行の中に誤りを表示、入力は残して編集を続ける。確定できたか取り消したら消す | 8.4〜8.7 |
| 編集の確定で保存に失敗 | 画面の内容は変えたまま（追加などと同じ）。お知らせを出す | 6.4 |
| `localStorage` に触るだけで例外（設定で禁止） | `main.js` で捕まえて `null` を渡す。`load` は `unavailable`。保存は試さず、お知らせを出したまま操作を続けられる | 6.4 |
| `setItem` が例外（容量不足） | 画面の状態はそのまま。お知らせを出す | 6.4 |
| 保存データが JSON として壊れている・形式が違う・項目が制約を満たさない | 空の一覧で始め、お知らせを出す。壊れた値は消さない（次の保存で上書きされる） | 6.5 |

## テスト方針
- **単体テスト（tests/unit/、Node 環境）**: `todo.js` の全関数（境界値: 200 文字と 201 文字、期限が昨日・今日・明日。`validateTitle` と `editTodo` を含む）と、
  `storage.js` の読み込み 4 通り（キーなし／正しい／壊れている／読めない）と保存 2 通り（成功／失敗）
- **画面テスト（tests/ui/、jsdom 環境）**: requirements.md の受け入れ条件ごとにテストを書き、テスト名の先頭に番号を入れる（例: `1.8: …`）。
  要件 7.1（ブラウザ）・7.2（キーボード）は自動テストにせず、手で確かめる。
  要件 8 は 8.1〜8.11 をすべて画面テストにする。Esc での取り消しは jsdom でキーの出来事を起こして確かめる。
  Enter での確定は、jsdom がフォームの暗黙の送信を再現しないため、追加と同じく `requestSubmit` で代えて確かめ、実際のキーは手で確かめる
  （2026-11-22 修正: 実装中に、Enter のキーの出来事では確かめられないと分かった）
- **「今日」の固定**（指摘 T3）: `createApp` が `today` を引数で受け取る。テストでは `2026-11-22` などに固定する
- **保存の失敗**（指摘 T5）: テスト用の偽 Storage を 3 種類作る（普通のもの／`setItem` で例外を投げるもの／何をしても例外を投げるもの）
- **閉じて開き直す**（指摘 T6）: 同じ偽 Storage で app を起動し直すことで、再読み込み【6.2】と開き直し【6.3】の両方を確かめたとする
- **通信しないこと**【7.3】: `src/` に `fetch` などの通信の API がないことをテストで確かめる
- テストは実装より先に書き、失敗することを確かめてから実装する
