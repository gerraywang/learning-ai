# Feature Specification: ブラウザで使う TODO アプリ

**Feature Branch**: `001-todo-app`（ブランチは作らず `main` で進める）

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "ブラウザで使う TODO アプリ。追加・完了・削除・期限・絞り込み。データは端末内に保存"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - やることを追加して、あとで見返す (Priority: P1)

利用者は、思いついたやることを 1 行で入力して一覧に加える。ブラウザを閉じて後日開いても、
同じ端末・同じブラウザなら一覧がそのまま残っている。

**Why this priority**: 追加と保存がなければ TODO アプリとして成り立たない。これだけで
「忘れないためのメモ」として価値がある最小の形（MVP）。

**Independent Test**: やることを 3 件追加 → ページを再読み込み → 3 件が追加した順に
表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 一覧が空, **When** 「牛乳を買う」と入力して追加する, **Then** 一覧に「牛乳を買う」が
   未完了として 1 件表示され、入力欄は空に戻る
2. **Given** やることが 2 件ある, **When** 3 件目を追加する, **Then** 3 件目が一覧の最後に表示される
3. **Given** やることが 3 件ある, **When** ページを再読み込みする（またはブラウザを閉じて開き直す）,
   **Then** 同じ 3 件が同じ順・同じ状態で表示される
4. **Given** 入力欄が空、または空白だけ, **When** 追加しようとする, **Then** 何も追加されず、
   入力が必要であることが利用者に分かる

---

### User Story 2 - 終わったやることに完了の印を付ける (Priority: P2)

利用者は、終わったやることに完了の印を付ける。間違えたときは未完了に戻せる。

**Why this priority**: 「何が残っているか」が分かることが TODO の主な価値。追加の次に重要。

**Independent Test**: やることを 1 件追加 → 完了にする → 見た目で完了と分かる → 再読み込み後も
完了のまま → 未完了に戻せる、を確かめる。

**Acceptance Scenarios**:

1. **Given** 未完了のやることがある, **When** 完了の印を付ける, **Then** そのやることは完了として
   表示され、未完了のものと見た目で区別できる
2. **Given** 完了のやることがある, **When** 印を外す, **Then** 未完了に戻る
3. **Given** やることを完了にした, **When** ページを再読み込みする, **Then** 完了の状態が保たれている

---

### User Story 3 - 要らなくなったやることを消す (Priority: P3)

利用者は、不要になったやることを一覧から削除する。

**Why this priority**: 一覧を整理できないと、使い続けるうちに見づらくなる。ただし追加・完了ほど
頻繁ではない。

**Independent Test**: やることを 2 件追加 → 1 件を削除 → 残り 1 件だけが表示され、再読み込み後も
削除したものが戻らないことを確かめる。

**Acceptance Scenarios**:

1. **Given** やることが 2 件ある, **When** 1 件を削除する, **Then** そのやることだけが一覧から消える
2. **Given** やることを削除した, **When** ページを再読み込みする, **Then** 削除したやることは表示されない
3. **Given** 完了・未完了どちらのやることでも, **When** 削除する, **Then** 同じように削除できる

---

### User Story 4 - 期限を付けて、過ぎたものに気づく (Priority: P4)

利用者は、やることに期限（日付）を付けられる。期限を過ぎてまだ終わっていないやることは、
一覧の中で目立って表示される。

**Why this priority**: 期限がなくても TODO は使えるが、締め切りのあるやることを落とさないために役立つ。

**Independent Test**: 期限が昨日のやることと明日のやることを追加 → 昨日の分だけが「期限切れ」と
分かる表示になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 追加する前, **When** やることと一緒に期限の日付を指定して追加する, **Then** 一覧に
   そのやることの期限が表示される
2. **Given** 追加する前, **When** 期限を指定せずに追加する, **Then** 期限なしのやることとして追加される
3. **Given** 期限が今日より前で未完了のやることがある, **When** 一覧を見る, **Then** そのやることは
   期限切れと分かる表示になる
4. **Given** 期限が今日より前でも完了しているやることがある, **When** 一覧を見る, **Then** 期限切れの
   表示にはならない
5. **Given** 期限が今日のやることがある, **When** 一覧を見る, **Then** 期限切れの表示にはならない

---

### User Story 5 - 状態で絞り込む (Priority: P5)

利用者は、一覧を「すべて」「未完了」「完了」で切り替えて表示できる。

**Why this priority**: やることが増えたときに残りだけを見たい。件数が少ないうちはなくても困らない。

**Independent Test**: 未完了 2 件・完了 1 件を用意 → 「未完了」で 2 件、「完了」で 1 件、
「すべて」で 3 件が表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 未完了 2 件・完了 1 件がある, **When** 「未完了」を選ぶ, **Then** 未完了の 2 件だけが表示される
2. **Given** 同上, **When** 「完了」を選ぶ, **Then** 完了の 1 件だけが表示される
3. **Given** 同上, **When** 「すべて」を選ぶ, **Then** 3 件すべてが表示される
4. **Given** 「未完了」を選んでいる, **When** あるやることを完了にする, **Then** そのやることは
   すぐに表示から外れる
5. **Given** 選んだ絞り込みに当てはまるやることが 0 件, **When** 一覧を見る, **Then** 該当がないことが
   分かる表示になる
6. **Given** 初めて開いたとき, **When** 一覧を見る, **Then** 「すべて」が選ばれている

---

### Edge Cases

- 入力の前後の空白は取り除いて保存する。取り除いた結果が空なら追加しない。
- 200 文字を超えるやることは追加できず、上限を超えていることが利用者に分かる。
- 同じ文言のやることを複数追加してもよい（別々のやることとして扱う）。
- 端末内に保存できない状態（ブラウザの設定で保存が禁止されている、容量が足りない など）では、
  保存できないことを利用者に知らせる。その場合も、開いている間は追加・完了・削除の操作はできる。
- 保存されているデータが壊れていて読めない場合は、空の一覧で始め、読み込めなかったことを
  利用者に知らせる。
- やることが 0 件のときは、空であることが分かる表示にする。
- 「今日」の判定は、利用者の端末の日付を基準にする。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、やることの文言（1〜200 文字）を入力して一覧に追加できなければならない（MUST）
- **FR-002**: システムは、前後の空白を除いて空になる入力、または 200 文字を超える入力を追加してはならず、
  その理由を利用者に示さなければならない（MUST）
- **FR-003**: システムは、やることを追加した順（古いものが上）に一覧表示しなければならない（MUST）
- **FR-004**: 新しく追加したやることは未完了の状態で始まらなければならない（MUST）
- **FR-005**: 利用者は、各やることの完了／未完了を切り替えられなければならない（MUST）
- **FR-006**: システムは、完了のやることを未完了のものと見た目で区別して表示しなければならない（MUST）
- **FR-007**: 利用者は、各やることを一覧から削除できなければならない（MUST）
- **FR-008**: 利用者は、やることの追加時に期限（日付）を任意で指定できなければならない（MUST）
- **FR-009**: システムは、期限のあるやることに期限の日付を表示しなければならない（MUST）
- **FR-010**: システムは、期限が今日より前で未完了のやることを「期限切れ」と分かるように
  表示しなければならない（MUST）
- **FR-011**: 利用者は、一覧の表示を「すべて」「未完了」「完了」で切り替えられなければならない（MUST）。
  初期値は「すべて」とする
- **FR-012**: システムは、すべてのやること（文言・完了状態・期限・順番）を利用者の端末内に保存し、
  ページの再読み込みやブラウザの再起動の後も復元しなければならない（MUST）
- **FR-013**: システムは、やることのデータを端末の外（サーバーや外部サービス）へ送ってはならない（MUST NOT）
- **FR-014**: システムは、保存や読み込みに失敗したとき、そのことを利用者に知らせなければならない（MUST）
- **FR-015**: システムは、一覧が空のとき、および絞り込みの結果が 0 件のとき、そのことが分かる表示を
  しなければならない（MUST）

### Key Entities

- **やること（Todo）**: 利用者が覚えておきたい 1 件の作業。属性は、文言（1〜200 文字）、
  完了しているかどうか、期限（日付・任意）、追加した順番を決める情報、他と区別するための識別子。
- **絞り込み条件（Filter）**: 一覧に何を表示するかの選択。「すべて」「未完了」「完了」のいずれか 1 つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて使う人が、説明を読まずに 10 秒以内に最初のやることを追加できる
- **SC-002**: 追加・完了の切り替え・削除・絞り込みの操作結果が、操作してから 0.1 秒以内に画面に反映され、
  利用者が待ちを感じない（やること 500 件まで）
- **SC-003**: ページの再読み込み・ブラウザの再起動の後、保存したやることが 100%（文言・状態・期限・順番）
  元どおりに表示される
- **SC-004**: 期限切れのやることを、一覧を開いて 3 秒以内に見つけられる
- **SC-005**: ネットワークに接続していない状態でも、すべての操作ができる
- **SC-006**: spec のすべての受け入れシナリオが、自動テストで確かめられる

## Assumptions

- 利用者は 1 人。同じ端末・同じブラウザで使う。アカウント登録・ログイン・端末間の同期は対象外。
- 対象はパソコンの一般的なブラウザ（最新版）。スマートフォン向けの最適化は今回の範囲外
  （表示が崩れない程度は求めるが、専用の操作性は求めない）。
- やることの文言の編集、期限の後からの変更は今回の範囲外（必要なら削除して追加し直す）。
  原則 III「シンプルさ優先」により、依頼にない機能は作らない。
- 削除は確認なしですぐに行い、元に戻す機能は持たない。
- 期限は日付のみ（時刻は扱わない）。
- 一覧の並べ替え（期限順など）、検索、カテゴリ・タグ、優先度、通知は今回の範囲外。
- 絞り込みの選択状態は保存しない（開き直すと「すべて」に戻る）。
- 表示言語は日本語のみ。
