# Feature Specification: やることの文言を後から編集する

**Feature Branch**: `002-edit-todo-text`（ブランチは作らず `main` で進める）

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "TODO の内容を後から編集できるようにしたい。
- 一覧の各 TODO で編集を始め、確定すると内容が変わる。取り消すと元の内容に戻る
- 内容の決まり（空や空白だけは不可、200 文字以内、前後の空白は除く）は追加のときと同じ
- 期限と完了かどうかは変えない（期限の編集は今回はしない）
- 編集した結果も、ほかの操作と同じように保存され、再読み込みしても残る"

## Clarifications

### Session 2026-11-22

- Q: 編集中に確定も取り消しもせず別の操作（入力欄の外をクリック、別のやることの完了切り替え・削除、絞り込みの切り替え、別のやることの編集開始など）をしたら、書きかけはどうなるか？ → A: 捨てる。確定は明示の確定操作だけで行い、中断は取り消しと同じ扱い（元の文言のまま）
- Q: 決まりに合わない文言（空・空白だけ・201 文字以上）で確定しようとしたら、画面はどうなるか？ → A: 編集中のまま、入力した文言も残して理由を示す。その場で直して確定するか、取り消せる
- Q: 確定・取り消しをキーボードで行えることを受け入れ条件にするか？ → A: する。Enter で確定、Esc で取り消し。画面上の確定・取り消しの操作も置く

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 書き間違えたやることを直す (Priority: P1)

利用者は、一覧にあるやることの文言を書き間違えたり、内容が変わったりしたときに、その場で
文言を直す。直した文言は、ページを開き直しても残っている。期限・完了の状態・一覧の中の位置は
変わらない。

**Why this priority**: これまでは削除して追加し直すしかなく、期限を付け直す手間や、一覧の
順番が変わる不便があった。文言を直して確定できること自体が、この機能の価値のすべて。

**Independent Test**: 期限付きのやることを 1 件追加 → 文言を編集して確定 → 新しい文言で
表示され、期限・完了状態・位置が変わっていない → 再読み込み後も新しい文言のまま、を確かめる。

**Acceptance Scenarios**:

1. **Given** 「牛乳を買う」というやることがある, **When** そのやることの編集を始めると,
   **Then** 現在の文言「牛乳を買う」が入った状態で文言を書き換えられるようになる
2. **Given** 「牛乳を買う」を編集している, **When** 「豆乳を買う」に書き換えて確定する,
   **Then** 一覧に「豆乳を買う」と表示され、編集中の状態が終わる
3. **Given** 期限が 2026-12-01 で未完了のやることを編集している, **When** 文言を書き換えて確定する,
   **Then** 期限は 2026-12-01 のまま、未完了のままである
4. **Given** 完了しているやることがある, **When** 文言を編集して確定する, **Then** 文言だけが変わり、
   完了のままである
5. **Given** やることが 3 件あり、2 件目を編集した, **When** 一覧を見る, **Then** 編集したやることは
   2 件目の位置のままである
6. **Given** 文言を編集して確定した, **When** ページを再読み込みする（またはブラウザを閉じて開き直す）,
   **Then** 編集後の文言で表示される
7. **Given** 「  豆乳を買う  」（前後に空白）に書き換えた, **When** 確定する, **Then** 前後の空白を
   除いた「豆乳を買う」になる
8. **Given** 「牛乳を買う」を「豆乳を買う」に書き換えている, **When** Enter キーを押す,
   **Then** 確定の操作をしたのと同じく「豆乳を買う」に変わる

---

### User Story 2 - 編集をやめて元に戻す (Priority: P2)

利用者は、編集を始めたものの直す必要がなかったと気づいたとき、編集を取り消す。書きかけの
内容は捨てられ、元の文言のまま残る。

**Why this priority**: 取り消せないと、編集を始めた時点で何かを確定しなければならず、
誤操作で文言を壊すおそれがある。ただし P1 の確定ができて初めて意味を持つ。

**Independent Test**: やることを 1 件追加 → 編集を始めて文言を書き換える → 取り消す →
元の文言のまま表示され、再読み込みしても元の文言のまま、を確かめる。

**Acceptance Scenarios**:

1. **Given** 「牛乳を買う」を編集して「豆乳を買う」に書き換えた（まだ確定していない）,
   **When** 取り消す, **Then** 「牛乳を買う」のまま表示され、編集中の状態が終わる
2. **Given** 編集を取り消した, **When** ページを再読み込みする, **Then** 元の文言で表示される
3. **Given** 編集を取り消した, **When** 同じやることの編集をもう一度始める, **Then** 元の文言
   「牛乳を買う」が入った状態から始まる（前回の書きかけは残らない）
4. **Given** 「牛乳を買う」を「豆乳を買う」に書き換えている, **When** Esc キーを押す,
   **Then** 取り消しの操作をしたのと同じく「牛乳を買う」のまま編集中の状態が終わる
5. **Given** 「牛乳を買う」を「豆乳を買う」に書き換えている（まだ確定していない）, **When** 別のやることの
   完了を切り替える（またはほかのやることの編集を始める・絞り込みを切り替える・文言の入力欄の外を
   クリックする）, **Then** 「牛乳を買う」のまま編集中の状態が終わる

---

### User Story 3 - 決まりに合わない文言では確定できない (Priority: P3)

利用者が、空や 200 文字を超える文言で確定しようとしても、文言は変わらず、理由が分かる。
決まりは、やることを追加するときと同じ。

**Why this priority**: 追加のときに守っている決まりが、編集で破られないようにする。
決まりに合う入力だけを扱う P1 があれば日常の利用はできるため、P3 とする。

**Independent Test**: やることを 1 件追加 → 文言を空にして確定 → 確定されず理由が示される →
201 文字にして確定 → 確定されず理由が示される → どちらの後も保存されている文言は元のまま、
を確かめる。

**Acceptance Scenarios**:

1. **Given** やることを編集している, **When** 文言を空にして確定しようとする, **Then** 文言は変わらず、
   編集中のままで、入力が必要であることが利用者に分かる
2. **Given** やることを編集している, **When** 空白だけにして確定しようとする, **Then** 文言は変わらず、
   編集中のまま入力した内容も残り、入力が必要であることが利用者に分かる
3. **Given** やることを編集している, **When** 201 文字にして確定しようとする, **Then** 文言は変わらず、
   編集中のまま入力した 201 文字も残り、上限を超えていることが利用者に分かる
4. **Given** やることを編集している, **When** ちょうど 200 文字にして確定する, **Then** その文言に変わる
5. **Given** 決まりに合わず確定できなかった, **When** 文言を直して確定する、または取り消す,
   **Then** それぞれ確定・取り消しが通常どおりできる

---

### Edge Cases

- 文言を変えずに確定した場合は、元の文言のまま編集中の状態が終わる（エラーにはしない）。
- 前後の空白を除くと元の文言と同じになる場合も、変えずに確定したのと同じ扱いにする。
- 同じ文言のやることが複数あっても、編集したやることだけが変わる。
- 確定は明示の確定操作だけで行う。編集中に確定も取り消しもせずにほかの操作（文言の入力欄の外を
  クリックする、完了の切り替え・削除・絞り込みの切り替え・新しいやることの追加）をすると、
  編集は取り消したのと同じ扱いになり、元の文言のまま残る。
- 一度に編集できるやることは 1 件だけ。編集中に別のやることの編集を始めると、前の編集は
  取り消される（書きかけは確定されない）。
- 編集を確定したときに端末内へ保存できなかった場合は、追加・完了・削除と同じく、保存できないことを
  利用者に知らせる。開いている間の表示は編集後の文言になる。
- 編集を確定した結果、そのやることが今の絞り込み条件に当てはまらなくなることはない（文言は絞り込みの
  条件ではないため）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、一覧に表示されている各やることについて、文言の編集を始められなければならない（MUST）
- **FR-002**: システムは、編集を始めたとき、そのやることの現在の文言を書き換えられる状態で示さなければ
  ならない（MUST）
- **FR-003**: 利用者は、編集中の文言を確定できなければならず、確定するとそのやることの文言が新しい文言に
  変わらなければならない（MUST）
- **FR-004**: 利用者は、編集を取り消せなければならず、取り消すとそのやることの文言は編集を始める前の
  文言のままでなければならない（MUST）。編集中に確定も取り消しもせずにほかの操作をした場合も、
  取り消したのと同じ扱いにしなければならない（MUST）
- **FR-005**: システムは、確定するとき、入力の前後の空白を除いた文言を新しい文言としなければならない（MUST）
- **FR-006**: システムは、前後の空白を除いて空になる文言、または 200 文字を超える文言では確定しては
  ならず、その理由を利用者に示さなければならない（MUST）。このとき編集中の状態と入力した文言は
  そのまま残さなければならない（MUST）。この決まりは、やることを追加するときと同じでなければ
  ならない（MUST）
- **FR-007**: システムは、文言の編集によって、そのやることの期限・完了状態・一覧の中の順番を変えては
  ならない（MUST NOT）
- **FR-008**: システムは、確定した文言を、ほかの操作と同じように利用者の端末内に保存し、ページの
  再読み込みやブラウザの再起動の後も復元しなければならない（MUST）
- **FR-009**: システムは、取り消された編集や確定されなかった書きかけの内容を保存してはならない（MUST NOT）
- **FR-010**: システムは、同時に 1 件のやることだけを編集中にしなければならない（MUST）
- **FR-011**: システムは、編集を確定したときに保存に失敗した場合、そのことを利用者に知らせなければ
  ならない（MUST）
- **FR-012**: 利用者は、確定と取り消しを、画面上の操作でも、キーボード（Enter で確定、Esc で取り消し）
  でも行えなければならない（MUST）

### Key Entities

- **やること（Todo）**: 001 で定義済み。本機能で変わるのは「文言」だけで、文言の決まり（前後の空白を
  除いて 1〜200 文字）も 001 と同じ。期限・完了状態・順番・識別子は編集で変わらない。
- **編集中の状態**: どのやることを編集しているか（0 件または 1 件）と、まだ確定していない書きかけの
  文言。画面を開いている間だけの一時的なもので、保存しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、一覧にあるやることの文言を、編集を始めてから 10 秒以内に直して確定できる
  （削除して追加し直すより少ない操作で済む）
- **SC-002**: 確定・取り消しの結果が、操作してから 0.1 秒以内に画面に反映される（やること 500 件まで）
- **SC-003**: 編集して確定したやることは、ページの再読み込み・ブラウザの再起動の後も 100% 編集後の
  文言で表示され、期限・完了状態・順番も 100% 元どおりである
- **SC-004**: 取り消した編集・決まりに合わず確定できなかった編集の後、保存されている文言が変わって
  しまう例が 0 件である
- **SC-005**: 本機能を加えた後も、001 の受け入れシナリオがすべて引き続き満たされる
- **SC-006**: 本 spec のすべての受け入れシナリオが、自動テストで確かめられる

## Assumptions

- 本機能は 001（ブラウザで使う TODO アプリ）の上に足す変更で、001 の追加・完了・削除・期限・絞り込み・
  保存の振る舞いはそのまま使う。
- 編集できるのは文言だけ。期限の編集は今回の範囲外（依頼による）。完了状態は編集中も変えない。
- 完了しているやることも、未完了のものと同じように文言を編集できる（依頼に制限がないため）。
- 編集の始め方（どこを押すと編集が始まるか）と、確定・取り消しの画面上の見た目は plan で決める。
- 一度に編集できるのは 1 件だけ。複数を同時に編集する必要はない（原則 III「シンプルさ優先」）。
- 編集の履歴（いつ・何から何へ変えたか）は持たない。確定後に元へ戻す機能（アンドゥ）も持たない。
- 編集中の書きかけの内容は保存しない。編集中にページを再読み込みすると、元の文言のまま表示される。
- 表示言語は日本語のみ（001 と同じ）。
