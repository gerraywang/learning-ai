<!-- Last updated: 2026-11-22 -->

- 変更前の状態: コミット `975c59f`（2026-11-22）。lab1・lab2 のフォルダをそのまま直す
- 両方とも「やらないこと」に **編集** を入れていた。範囲外 → 範囲内に変える変更なので、
  古い記述（「編集はしない」）が残らないかも見どころ

## 変更の依頼（両方に同じ文を渡す）
```text
TODO の内容を後から編集できるようにしたい。
- 一覧の各 TODO で編集を始め、確定すると内容が変わる。取り消すと元の内容に戻る
- 内容の決まり（空や空白だけは不可、200 文字以内、前後の空白は除く）は追加のときと同じ
- 期限と完了かどうかは変えない（期限の編集は今回はしない）
- 編集した結果も、ほかの操作と同じように保存され、再読み込みしても残る
```

### lab2 に残った既知の穴（直さないと決めた、2026-11-22）
- **日本語入力の変換中に Esc を押すと、編集が取り消される**（`src/app.js` の Esc の処理が `isComposing` を見ていない）。
  変換を取り消すつもりの Esc で、書きかけの編集が消える。lab1 は変換中の Esc を無視している（テストあり）
- 編集中の行の外をクリックしたとき: lab1 は取り消す、lab2 は編集が続く（穴というより仕様の差）
- 手での確認（lab1 の T022、lab2 の 12.2）はどちらも未実施。変換を確定する Enter で編集まで確定しないかは、ブラウザで確かめていない

## 学んだこと（2026-11-22 修了）

- **Kiro は一気に実装されたが、Spec Kit が気づいたこと（編集中の Enter キー、ほかのイベント）が穴になっているおそれがある**
- 確かめた結果（裏付け）: ほかのイベントは lab2 でも要件 8.10 で扱われていた（行の外のクリックだけ仕様が違う）。
  日本語入力の変換中の Esc は、lab2 で実際に穴になっていた。lab1 で拾えたのは clarify（人への質問）と research（調べる段）があったから
